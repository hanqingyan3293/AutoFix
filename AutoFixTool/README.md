# Autodesk 修复工具箱（AutoFix）

免费的、无需登录的 Autodesk 安装故障修复工具，图形界面。

- **无授权校验、无登录、无任何网络请求** —— 完全离线运行
- 修复逻辑独立实现，基于标准 Windows Installer / 注册表 / 服务故障处理

## 编译

```
dotnet build AutoFixTool/AutoFix.csproj -c Release
```

| 版本 | 产物 | 运行要求 |
| --- | --- | --- |
| 标准版 | AutoFixTool/bin/Release/net472/AutoFix.exe | .NET Framework 4.7.2+ |
| 兼容版 | AutoFixTool/bin/Release/net40/AutoFix.exe | .NET Framework 4.0+（Win7 SP1 起） |

两版共用同一份源码，仅目标框架不同。产物约 95 KB，无第三方 DLL 依赖。

## 预演模式

顶栏右侧有「预演模式（只列计划，不实际执行）」开关。开启后：

- 所有修复操作**只输出计划，不执行任何改动**；日志中每条以 `[预演] 将执行：` 开头
- 结果弹窗显示「共 N 项操作，均未实际执行」并给出计数
- **不要求管理员权限**（因为不做任何实际改动）

现有 33 处拦截点覆盖：停服务、执行命令、结束进程、删目录/文件、删注册表键/值、
改 ACL、写注册表值、写文件、清理临时文件、清理卷缓存、创建还原点、语言切换、CAD 瘦身与降级。

建议用法：**先开预演跑一遍，确认影响清单后再关掉执行**。

## 检测结果页

点「环境检测 → 检测并查看报告」打开独立的检测结果页：

```
检测结果      只读检测 · 未修改任何设置 · 生成于 …
─────────────────────────────────────────────────
环境概览                          [ ] 只显示需要注意的项
  分组       检查项          状态 / 当前值      说明
  系统环境   操作系统        Windows 10 …
  系统环境   当前权限        管理员
  …
─────────────────────────────────────────────────
已安装的 Autodesk 系列产品   （点击分组行可折叠/展开）
  名称   版本   发布者   安装位置   安装日期   架构   占用
─────────────────────────────────────────────────
检测到 N 个产品（M 个分组） · 环境检查 K 项，X 项需要注意   [导出报告]
```

**体检项分六组：**

| 分组 | 检查项 |
| --- | --- |
| 系统环境 | 操作系统、系统架构（含本程序位数）、当前权限、.NET Framework 版本、系统时间（含年份合理性）、各固定磁盘剩余空间 |
| 网络与安全 | hosts 文件（Autodesk 相关重定向）、已注册的安全软件 |
| 目录与路径 | 临时目录、我的文档（是否指向失效磁盘）、C:\Windows\Installer 是否存在 |
| Autodesk 组件 | AdskLicensingService 状态、AdskLicensing 目录、ProductInformation.pit（含权限）、Genuine Service 目录、FLEXnet 许可数据、AdODIS、AdskIdentityManager、Autodesk Access |
| Windows Installer | msiserver 状态、挂起的重启标记、IFEO 调试器劫持项数量 |
| 运行库 | 已安装的 VC++ 运行库清单（检查是否含 2015-2022 系列） |

每个检查项有三档状态：**正常**（绿）、**需要注意**（橙，加粗）、**信息**（灰）。
橙色项会在「说明」列指出与哪个修复功能对应 —— 例如「我的文档指向的磁盘 D: 不存在（可能引发错误1603）」。

**只显示需要注意的项**：勾选后体检表只留橙色项，快速定位异常。

**产品列表**按产品分组（分组键 = 产品名去掉年份与版本号），**组内每条记录仍各占一行**：

- 分组组头行显示产品名与记录条数，点击即可折叠 / 展开，也可用「折叠全部分组」一次收起
- 只有一条记录的分组不建组头行，直接显示该行，避免噪音
- 产品表不提供排序，以免打乱分组结构
- 显示名称、版本、发布者、安装位置、安装日期、架构、占用空间

「导出报告」把完整结果存为 txt（UTF-8）。

## 严格只读

检测过程**不写入任何系统状态**：只读注册表、只读文件、只查询服务状态与 WMI，
不做可写性探测（不创建测试文件），不修改 ACL。

唯一的写入发生在你主动点「导出报告」并选择保存位置时（写出一个 txt），与系统状态无关。

## 安全设计

- **修复前必须二次确认**：确认框列出**具体**将执行的动作（确切的服务名、目录路径、注册表键）。
  默认按钮落在**「取消」**，误按回车即取消、不会执行。只读的「环境检测」不弹确认。
- **非管理员拦截**：未提权时点修复功能会被对话框拦下，不会执行到一半失败。
- **执行不阻塞界面**：修复在后台线程运行，日志实时回显；执行期间所有按钮禁用，避免并发触发。
- **失败可辨识**：结果含「失败」「异常」时，弹窗标题为「执行失败」并使用错误图标。

## 需要注意的两项

以下两项是忠实还原原程序逻辑的结果，但**判断依据较宽，影响范围可能超出 Autodesk**，执行前请务必确认：

| 功能 | 风险 |
| --- | --- |
| 错误4000 / 错误-9 修复 | 会删除 HKLM\\SOFTWARE\\Classes 下的**所有叶子键**。该分支覆盖全系统的文件关联信息，影响面可能很广。 |
| 错误3 修复 | 会删除 C:\\ProgramData 下**名称含特殊字符**的文件夹，以及名为 Package Cache / Packages 的文件夹。判断仅基于名称特征，可能命中非 Autodesk 目录。 |

这两项我没有为了「安全」而擅自改变行为，但它们值得你在使用前明确知情。

## 与原实现的差异

有三处我有意偏离了原程序，都会影响行为，明确列出：

| 项目 | 原实现 | 本工具 | 原因 |
| --- | --- | --- | --- |
| 目录权限授予对象 | `Everyone:(OI)(CI)F`（takeown + icacls） | 当前用户 / Administrators / Users | 授予 Everyone 完全控制是安全倒退，不沿用 |
| 3ds Max 语言切换 | 硬编码 15.0–26.0 共 12 个版本键 | 枚举 `HKCU\\...\\Autodesk\\3dsMax` 下实际存在的子键 | 新版本自动覆盖，不会误写不存在的版本 |
| hosts 修复 | 只清除 rj818.com 相关条目 | 清除所有「屏蔽 Autodesk 相关域名」的条目 | 原逻辑服务于特定厂商域名，改为通用判据 |

## 已知边界

- 未在实机运行验证（沙箱无法启动需要提权的 GUI 程序），行为描述来自代码实现。
- 需联网的功能（错误16 / 错误4005 / WebView2）**未纳入**，以保持完全离线运行。
- 首次运行有 SmartScreen 提示（未签名的新程序），点「更多信息 → 仍要运行」。
- 部分杀软可能告警（本类工具会停服务、改注册表权限）。
- 建议先在测试机验证再用于生产环境。

## 实现说明

修复逻辑从 Autobox 1.0.4 的对应方法逐条提取后**独立重新实现**，包括各修复项的
注册表分支、账户权限组合、服务与进程名、目录路径等具体行为。

未复制 Autobox 的界面资源（图标）、配色、品牌标识与文案。界面布局采用通用的
分类导航 + 按钮网格模式。
